## 1. Продукт

### 1.1. Суть
Career Hunter — локальное desktop-приложение для пользователя в России, ищущего работу в ИБ. Оно собирает вакансии из разрешённых источников, нормализует и дедуплицирует их, извлекает факты с цитатами, проверяет доступность работы из России, считает объяснимую оценку и ведёт трекер откликов. Браузерное расширение помогает **по действию пользователя** переносить в приложение вакансии с площадок без открытого API.

### 1.2. Цели
- Единая локальная база вакансий из РФ и зарубежных источников.
- Не терять вакансии из-за отсутствия зарплаты или нестандартного названия.
- Отличать «Remote» от реальной возможности работать из России.
- Объяснимая оценка: пользователь видит факторы, цитаты и риски.
- Вердикт по каждой вакансии: «Откликаться / Проверить условия / Пропустить».
- Продукт полезен, даже если все автоматические коннекторы недоступны (ручной импорт и расширение).
- Помощь в подготовке откликов без выдумывания фактов; отправка — только пользователем.

### 1.3. Не делаем (MUST NOT)
- Обход CAPTCHA, антибот-защиты, авторизации, paywall, лимитов; ротация прокси; подмена окружения браузера; любая маскировка автоматизации.
- Фоновый краулинг площадок расширением (самостоятельное открытие страниц, пролистывание выдачи, массовая дозагрузка карточек).
- Любая автоматизация LinkedIn: расширение не содержит парсера LinkedIn и не имеет прав на `linkedin.com`. Для LinkedIn доступен только ручной ввод (вставка URL/текста, импорт писем-оповещений).
- Автоматическая отправка откликов в MVP (Auto Apply — Этап 8, выключен по умолчанию, только для белого списка источников).
- Сбор персональных данных рекрутеров (ФИО, телефоны, email, ссылки на профили).
- Выдумывание навыков, опыта, достижений, ответов на вопросы работодателя.
- Юридические гарантии трудоустройства, выплат или допустимости найма.
- Публикация или передача собранных данных третьим лицам.

### 1.4. Принципы
1. **Неизвестное ≠ отрицательное.** Unknown не исключает вакансию и не обнуляет оценку.
2. **Исключение только по подтверждённому основанию** (Confirmed + цитата).
3. **Объяснимость:** любой вывод показывает причину и цитату.
4. **Человек решает:** система рекомендует, пользователь действует.
5. **Локальность:** данные по умолчанию не покидают компьютер.
6. **Устойчивость:** отказ любого источника не ломает остальные; продукт полезен без LLM и без коннекторов.

### 2.4. Предпочтения и исключения
Предпочтения: полноценная работа (не бесконечная стажировка); техническая работа с системами, сетями, приложениями, уязвимостями, СЗИ; junior/entry-level с реалистичными требованиями; компании любого типа, кроме Big Tech как целевой категории.
Жёсткие исключения применяются **только** по правилам раздела 9.5.

### 2.5. Реестр навыков (Skill ledger)
Поля записи: `skill`, `level` (знаком / рабочий / уверенный), `evidence_type` (работа, сертификат, CTF/лаборатория, проект, курс, баг-баунти), `link_or_note`, `date`. Skills Fit и Copilot используют **только** навыки из реестра.

### 2.6. Профили поиска (SearchProfile)
Несколько профилей (например, «Pentest — РФ», «AppSec — международные»): направления, пороги, источники, расписание, уведомления. Профиль кандидата и реестр навыков общие.

## 4. Источники вакансий

### 4.1. Классы доступа
| Класс | Название | Правило |
|---|---|---|
| A | Официальный API / фид / RSS | Предпочтительно. Соблюдать лимиты, атрибуцию, запреты на перераспространение |
| B | API от имени пользователя (OAuth) | Токены только в системном хранилище; права минимальные |
| C-assist | Захват по действию пользователя через расширение | Только на открытой пользователем странице, по клику/горячей клавише; без фоновых запросов; включается **по сайтам** после решения go на Этапе 0 |
| D | Ручной импорт | URL, вставка текста, файл, `.eml` — всегда доступен |
| E | Недоступно автоматически | Остаётся в реестре со статусом; только класс D |

Принадлежность к C-assist **не означает разрешённость**: площадка может запрещать автоматизированный сбор в условиях. Каждый сайт по умолчанию **выключен** для расширения, пока в `SourceTerms` не стоит `capture_allowed = true` с датой проверки условий.

### 4.3. SourceTerms (запись реестра, хранится в БД и `sources.yaml`)
`source_id`, `name`, `access_class`, `auth_type`, `tos_url`, `tos_checked_at`, `rate_limit`, `min_interval_sec`, `robots_status`, `attribution_required` (+ текст/ссылка), `redistribution_allowed`, `capture_allowed`, `auto_apply_allowed` (по умолчанию false), `enabled`, `last_success_at`, `status`, `last_error`.

### 4.4. Правила сбора (MUST)
- Честный User-Agent: `CareerHunter/<ver> (<contact>)`; для hh.ru — `HH-User-Agent` в требуемом формате.
- Токен-бакет на каждый источник; значения по умолчанию не выше заявленных площадкой.
- Условные запросы (ETag/If-Modified-Since), кэш, экспоненциальный backoff с jitter.
- Circuit breaker: после N подряд ошибок 403/429 источник приостанавливается, пользователю показывается причина.
- При CAPTCHA/блокировке — остановить сценарий, передать управление пользователю или пометить источник недоступным.
- Учитывать `robots.txt` для страниц и фидов.
- Расписание хранится в БД (`last_run_at`); при запуске приложения источник опрашивается, только если интервал истёк (первый тик таймера не должен нарушать суточные лимиты). Применять jitter.
- Классы действий коннектора: read / write / irreversible. Write и irreversible (отклик, отказ, правка резюме) — только после явного подтверждения пользователя и с записью в журнал.
- Хранить `url`, дату получения, `attribution`.

### 4.5. Расписание коннекторов класса A (значения по умолчанию, настраиваемые, не быстрее лимитов площадки)
Remote OK — раз в 2 ч; WWR — раз в 4 ч; ATS (watchlist) — раз в 6 ч; Jobicy — раз в 6 ч; Remotive и Himalayas — выключены.

## 5. Расширение браузера (подробно)

### 5.1. Назначение и границы
Расширение переносит в приложение вакансии, которые пользователь **сам открыл и сам решил сохранить**. Оно не краулит, не скроллит, не открывает страницы, не кликает на сайтах, не отправляет отклики.

### 5.2. Режимы захвата
| Режим | Описание | По умолчанию |
|---|---|---|
| Capture current vacancy | Кнопка в popup / горячая клавиша на странице вакансии; парсится полное описание → `completeness = full` | Включён для разрешённых сайтов |
| Capture visible results | Кнопка на странице выдачи: парсятся карточки, **уже отрисованные на странице** → `completeness = partial` | Включён для разрешённых сайтов |
| Auto-capture on open | Автоматический захват при открытии страницы вакансии/выдачи пользователем | **Выключен**; включается пользователем по сайтам через `optional_host_permissions` и только если для сайта `capture_allowed = true` |
| Manual paste | Вставка URL/текста в приложении (без расширения) | Всегда |

Бесконечная прокрутка: расширение не прокручивает страницу; захватывается то, что отрисовано на момент клика. Для auto-capture допускается `MutationObserver` на уже загруженный DOM с дебаунсом.

### 5.3. Манифест (Chrome/Edge)
```json
{
  "manifest_version": 3,
  "name": "Career Hunter",
  "version": "1.0.0",
  "permissions": ["activeTab", "scripting", "storage", "alarms"],
  "host_permissions": ["http://127.0.0.1/*"],
  "optional_host_permissions": [
    "https://hh.ru/*", "https://career.habr.com/*", "https://www.avito.ru/*"
  ],
  "background": { "service_worker": "background.js", "type": "module" },
  "action": { "default_popup": "popup/popup.html" },
  "options_page": "options/options.html",
  "commands": {
    "capture-page": { "suggested_key": { "default": "Alt+Shift+S" }, "description": "Сохранить страницу в Career Hunter" }
  }
}
```
- Статических `content_scripts` на сайтах площадок **нет**: парсер внедряется через `chrome.scripting.executeScript` по жесту пользователя (activeTab).
- Права `tabs` не запрашивать. `linkedin.com` не упоминается нигде в манифесте и коде.
- Паттерн `http://127.0.0.1/*` покрывает любой порт [проверить в целевых браузерах].
- Firefox: отдельный `manifest.firefox.json` (`background.scripts` вместо `service_worker`, `browser_specific_settings.gecko`); различия API изолировать тонким слоем совместимости.

### 5.4. Парсеры
- Логика парсеров поставляется внутри расширения (MV3 запрещает удалённый код).
- **Селекторы — данные:** `selectors.json` со схемой `{ site, page_type, version, fields: { title: [css…], company: […], salary: […], … } }`, с несколькими резервными селекторами на поле. Приложение раздаёт актуальный файл через `GET /v1/parsers`; файл подписан (Ed25519), расширение проверяет подпись встроенным публичным ключом и откатывается на встроенную версию при ошибке. Это позволяет чинить поломки без выпуска в магазине.
- Предпочитать семантические и структурные источники: JSON-LD (`JobPosting`), атрибуты `data-qa`/`itemprop`; не опираться на обфусцированные классы (Авито — особенно хрупко).
- Парсер возвращает `completeness` и список не найденных полей; **пустое значение никогда не подменяется выдуманным**.
- Вырезать контактные данные рекрутеров (белый список полей; регулярные выражения для email/телефонов в описании заменяются плейсхолдерами `[contact removed]`).
- Контрактные тесты на сохранённых HTML-страницах (`tests/fixtures`).

### 5.5. Background (service worker)
- Не использовать `setInterval`: периодические задачи — `chrome.alarms` (минимальный период ≥ 1 мин).
- Очередь исходящих в `chrome.storage.local` (ключ `outbox`) с атомарной записью (одна функция-мьютекс для чтения-изменения-записи), потолок: 500 записей или 5 МБ, TTL 7 дней; при переполнении старые удаляются, пользователь видит предупреждение в popup.
- Отправка пачками (до 50 элементов) на `POST /v1/vacancies`; повтор с backoff при недоступности; запросы выполняет **только** background (content/injected-скрипты не обращаются к localhost).
- Идемпотентность: каждому элементу присваивается `idempotency_key = sha256(source + source_job_id|url + captured_day)`.
- Ограничение частоты применяется к запросам **к площадкам** (их расширение не делает), а не к localhost.

### 5.6. Popup и Options
Popup: статус соединения (подключено / приложение не запущено / не сопряжено / токен отклонён), число вакансий в очереди, кнопки «Сохранить вакансию», «Сохранить результаты на странице», переключатель сайта (вкл/выкл), последний результат («сохранено N, оценка …»).
Options: ввод кода сопряжения, порт, список разрешённых сайтов (с запросом optional permissions), очистка очереди, экспорт диагностики без токена.
Страничный индикатор (бейдж на карточке) — **MAY**, только при включённом auto-capture для сайта.

### 5.7. Сопряжение и аутентификация
1. Приложение при первом запуске генерирует случайный токен (≥ 256 бит), хранит его в системном хранилище и показывает код сопряжения (токен в кодированном виде для копирования).
2. Пользователь вводит код в Options расширения; токен сохраняется в `chrome.storage.local`.
3. Все запросы `Authorization: Bearer <token>`; в приложении есть «Перевыпустить токен» (старый немедленно недействителен) и список сопряжённых клиентов.
4. Дополнительно: сервер принимает только `Host: 127.0.0.1:<port>`/`localhost:<port>` (защита от DNS rebinding) и, если присутствует заголовок `Origin`, только `chrome-extension://<allowed_id>` / `moz-extension://<allowed_id>`.
5. CORS: заголовки `Access-Control-Allow-*` **не отдаются** (расширению с host-правами они не нужны). Ответ на `OPTIONS` — 204 без ACAO. `CorsLayer::permissive()` и `Allow-Origin: *` **запрещены**.
6. Усиление (SHOULD, Этап 8): Native Messaging вместо HTTP — закрывает открытый порт.

## 6. Локальный Ingest API

База: `http://127.0.0.1:<port>` (порт по умолчанию 8765; если занят — автоперебор из списка 8765–8775, выбранный порт показывается в UI и записывается в файл конфигурации; приложение MUST NOT падать при занятом порте).
Версионирование: префикс `/v1`. Максимальный размер тела — 2 МБ; элементов в пачке — до 50.

### 6.1. Эндпоинты
| Метод и путь | Auth | Назначение |
|---|---|---|
| `GET /v1/health` | нет | `{status, api_versions, app_version}` — без данных пользователя |
| `GET /v1/status` | да | `{queue_depth, jobs_total, sources: [...]}` |
| `POST /v1/vacancies` | да | Приём пачки захваченных вакансий |
| `GET /v1/parsers` | да | Актуальный `selectors.json` + подпись |
| `GET /v1/sites` | да | Список сайтов и `capture_allowed` из реестра (расширение показывает/блокирует кнопки) |

### 6.2. Схема элемента `POST /v1/vacancies`
```json
{
  "schema_version": 1,
  "client": { "kind": "extension", "version": "1.0.0", "browser": "chrome" },
  "items": [{

    "captured_by": "user_action",
    "captured_at": "2026-11-25T10:00:00Z",
    "page_type": "vacancy_page",
    "completeness": "full",
    "source": "hh",
    "source_job_id": "123456789",
    "url": "https://hh.ru/vacancy/123456789",
    "title": "Junior Pentester",
    "company": "ООО «Безопасные технологии»",
    "description_html": "<p>…</p>",
    "salary_text": "90 000 – 120 000 ₽ на руки",
    "location_text": "Москва",
    "experience_text": "От 6 месяцев",
    "employment_text": "Полная занятость",
    "schedule_text": "5/2",
    "posted_text": "25 ноября",
    "missing_fields": ["posted_at"]
  }]
}
```
Обязательные поля элемента: `idempotency_key`, `source`, `url`, `title`, `completeness`, `captured_at`. Неизвестные поля игнорируются, но логируются на уровне debug.

### 6.3. Ответы
- `202 Accepted`: `{ "request_id": "…", "accepted": [{ "idempotency_key": "…", "job_id": "uuid", "status": "queued" }], "rejected": [{ "idempotency_key": "…", "error": "missing_field:title" }] }`. Оценка в ответе **не возвращается**: обработка асинхронная; расширение может узнать результат через `GET /v1/status` или не узнавать (результат виден в приложении).
- `400` — неверный формат; `401` — нет/неверный токен; `403` — неверные `Host`/`Origin`; `413` — слишком большое тело; `429` — приём приостановлен (очередь переполнена), с `Retry-After`; `503` — приложение запускается.
- Серверная валидация: `source` из списка разрешённых и с `capture_allowed = true` (иначе элемент отклоняется `site_not_allowed`).

### 6.4. Идемпотентность и дозагрузка (upsert)
- Ключ идентичности: `(source, source_job_id)`, при его отсутствии — канонический URL.
- `partial` создаёт запись со статусом полноты `partial`. Позднее `full` для того же ключа **дополняет** запись (описание, поля) и запускает повторную обработку; `partial` никогда не затирает `full`.
- Повторная отправка той же пачки не создаёт дублей (идемпотентность по `idempotency_key`).
- Для `partial`: Score считается, но категория Strong недостижима, Confidence не выше Low; в UI — пометка «открой вакансию для полного разбора».

## 8. Конвейер обработки (pipeline)

Очередь заданий персистентная (`job_queue`): переживает перезапуск, повторяет с backoff, не допускает дублирования задач. UI не блокируется.

```
ingest → normalize → dedup → classify(rules → [LLM]) → evidence(verify) →
eligibility → hard-filters → legitimacy → score → notify
```

### 8.1. Нормализация
- HTML → безопасный HTML (`ammonia`, белый список тегов) + чистый текст; URL → канонический (удаление `utm_*`, `from`, идентификаторов сессии и т. п.).
- Зарплата: сохранить исходный текст; разобрать валюту, min/max, период, gross/net; `salary_source ∈ {structured, parsed_text, estimated, unknown}`; не смешивать год/месяц; gross≠net без расчёта; неизвестная база → помечается и не используется для жёсткого исключения.
- `content_hash` = SHA-256 нормализованного (title, company, description_text, ключевые поля). Хэш используется для обнаружения изменений и кэша LLM, **но не как основной ключ дедупликации**.

### 8.2. Дедупликация
| Уровень | Сигнал | Действие |
|---|---|---|
| 1 | Совпадение `(source, source_job_id)` или канонического URL | Тот же объект: обновление, `job_event` |
| 2 | Совпадают нормализованные (компания, название, город/страна) и сходство описаний ≥ 0,9 (shingles/SimHash), даты в пределах ~30 дней | Автообъединение; ссылки сохраняются в одной карточке |
| 3 | Та же компания, похожее название, сходство 0,7–0,9 либо различаются страна/команда/уровень/условия | «Возможный дубль»: не объединять, предложить ручное решение |
| 4 | Пара (компания, название) вновь появилась после закрытия или через N дней | Не новая вакансия: `reposted_count++`, сигнал legitimacy |
Пороги — начальные, калибруются на golden dataset. Ручные решения запоминаются и не перезаписываются. Ложное объединение серьёзнее пропуска дубля.

### 8.3. Жизненный цикл
`New → Active → Changed → Stale (не подтверждена > 14 дн.) → Closed`. Closed — только при явном сигнале источника (404, «в архиве») либо исчезновении из выдачи при успешном обновлении; сетевая ошибка/лимит → статус не меняется (Unknown). Проверка «живости» — для сохранённых и высоко оценённых вакансий и перед откликом (только допустимыми способами; для источников без разрешённого фонового доступа — по действию пользователя).

### 8.4. Классификация (ступенчато)
1. **Правила и словари** (YAML, версионируются; Приложение B): направление, уровень, график, формат, SOC, 2/2, гео-признаки, особые требования РФ.
2. **LLM-извлечение** (опционально): только для полей, оставшихся Unknown, и только для вакансий, прошедших жёсткие фильтры. Вход — очищенный текст в отдельном поле; ответ строго по JSON-схеме (поле, значение, цитата); temperature 0; кэш по `content_hash + prompt_version + model`. Модель без инструментов и без доступа к сети.
3. **Согласование:** расхождение правил и модели → `Conflicting`, показываются обе цитаты.
Без LLM шаг 2 пропускается, непокрытые поля остаются Unknown.

### 8.5. Evidence и верификация
Критичные поля: направление, уровень, формат, тип занятости, график, зарплата, доступность из РФ, SOC-смены, Big Tech, продажи, неоплачиваемая стажировка.
Каждая запись: значение, статус (**Confirmed** — прямо указано и есть цитата; **Inferred** — выведено; **Unknown**; **Conflicting**), цитата ≤ 300 символов с позицией, автор вывода и версия, уверенность 0–1.
**Правило верификации (MUST):** цитата должна буквально (после нормализации пробелов) входить в сохранённый `description_text`/поля вакансии; проверка программная. Нет цитаты или не найдена → статус понижается до Inferred/Unknown, событие логируется. Вывод LLM без валидной цитаты не может быть Confirmed.

### 8.6. Eligibility (доступность из РФ)
Статусы: `russia_eligible`, `worldwide`, `emea`, `country_restricted`, `russia_excluded`, `eligibility_unknown`, `payment_unclear`.
Правила применяются сверху вниз, первое сработавшее задаёт статус; каждое срабатывание создаёт Evidence:
1. Явное исключение России/СНГ/«sanctioned countries», «except Russia» → `russia_excluded`.
2. Россия названа среди разрешённых → `russia_eligible`.
3. Список разрешённых стран без России; «must reside/be located in <страна>» → `country_restricted`.
4. «authorized to work in», «right to work», «no sponsorship», локальное юрлицо → `country_restricted` либо `payment_unclear` (по контексту).
5. «Worldwide / Anywhere / Work from anywhere» без оговорок → `worldwide` (проверить договор и исключения).
6. Регион (EMEA, Europe) или часовой пояс без перечня стран → `emea` / `eligibility_unknown` (принадлежность России к Европе — не подтверждение).
7. Просто «Remote» → `eligibility_unknown`.
Источники подтверждения по приоритету: текст вакансии → FAQ/страница найма компании → поля ATS → сторонние сведения (только Inferred со ссылкой и датой). Срок годности проверки — 30 дней (настраиваемо), затем «перепроверить». Если статус неизвестен, вакансия остаётся в выдаче с пометкой «требуется проверка». Юридических гарантий приложение не даёт.

### 8.7. Жёсткие фильтры
Rejected допустим **только** при наличии основания со статусом Confirmed и цитатой. Основание Inferred даёт максимум Low match + «проверить».
| Правило | Условие | Оговорки |
|---|---|---|
| Неоплачиваемая стажировка | Confirmed: прямо указано отсутствие оплаты | Слова «стажировка» недостаточно |
| SOC со сменами | Confirmed: SOC + (2/2 или сменный или 24/7) | SOC при 5/2 не исключается |
| Чистые продажи | Confirmed: обязанности — продажи без технической составляющей | Pre-Sales с техническими обязанностями не исключается |
| Зарплата в РФ ниже минимума | Published; понятны сумма, валюта, период, база | При пересчёте gross→net в пределах ±10% от порога — не исключать, пометить |
| Russia excluded | Confirmed | `eligibility_unknown` исключением не является |
| Big Tech | Компания из редактируемого списка, основание сохранено | Режим «исключать/понижать»; неизвестный размер — не основание |
Каждое исключение показывает правило, цитату и кнопку «вернуть в выдачу» (решение запоминается).

### 8.8. Достоверность вакансии (Legitimacy)
Отдельный сигнал, **не влияет на Match Score**; уровень сомнений Низкий/Средний/Высокий + список сигналов с фактами; пользователь может включить как фильтр. Говорим «признаки», не «мошенничество».
Сигналы: ≥3 повторных публикаций за 90 дней / «висит» дольше срока; нет юрлица/сайта/карьерной страницы; вакансии нет на официальной карьерной странице (если доступна); просьба заплатить (обучение, оформление, депозит); контакт только через мессенджер/личную почту, домен не совпадает; зарплата сильно выше рынка при низких требованиях; шаблонное описание без обязанностей; текст содержит обращения к ИИ/команды (prompt injection).

### 8.9. Особые требования ИБ в РФ
Флаги (теги, не исключения): допуск к государственной тайне, лицензии ФСТЭК/ФСБ, КИИ, аттестация объектов, сертифицированные СЗИ. Допуск к ГТ создаёт предупреждение «может накладывать ограничения; уточнить у работодателя».

## 9. Ранжирование (Match Score)

### 9.1. Компоненты и веса по умолчанию (сумма 100; настраиваются)
| Компонент | Вес | Значение 0–1 |
|---|---|---|
| Role Fit | 25 | Направление высокого приоритета = 1; Pre-Sales 0,6–0,8; смежные 0,4–0,6; нерелевантное 0; по обязанностям, не только по заголовку |
| Seniority Fit | 15 | Intern/Junior/entry = 1; Middle «от 1 года» = 0,6; «от 3 лет» и выше = 0–0,3; Unknown = 0,5 |
| Skills Fit | 15 | Доля требуемых навыков, подтверждённых в Skill ledger; нет данных = 0,5 |
| Location & Eligibility | 15 | РФ: Москва = 1; удалённо = 1; другой регион офис = 0. Международные: eligible = 1, worldwide = 0,6, emea = 0,4, unknown/payment_unclear = 0,5 (низкая Confidence) |
| Compensation Fit | 10 | В цели или выше = 1; между минимумом и целью 0,6–0,9; Unknown = 0,5 |
| Employment Fit | 8 | Трудовой + 5/2 = 1; допустимый по профилю contractor/B2B 0,6–0,8; Unknown = 0,5 |
| Company Fit | 7 | Не Big Tech и предпочтительный тип = 1; Big Tech (режим «понижать») = 0,2; неизвестный размер = 0,5 |
| Freshness | 5 | ≤ 3 дн. = 1, линейно до 0 к 30 дням; репосты не «освежают» |

### 9.2. Правила
- `Score = Σ(вес × значение)`; неизвестные компоненты получают 0,5 и снижают Confidence.
- **Confidence** (High/Medium/Low) — по доле критичных полей со статусом Confirmed; `partial`-записи не выше Low.
- **Barrier:** `russia_excluded` и Rejected по 8.7 → Rejected; `eligibility_unknown`/`payment_unclear`/`worldwide` без проверки → категория не выше Potential.
- Категории: **Strong** — Score ≥ 75, Confidence ≥ Medium, нет барьеров; **Potential** — 55–74, либо ≥ 75 при Low confidence/неподтверждённой доступности; **Stretch** — Role Fit ≥ 80 и Seniority Fit < 50 (причина разрыва явная); **Low** — < 55 или Inferred-основание исключения; **Rejected** — правило 8.7.
- Вердикт: Strong → «Откликаться»; Potential/Stretch → «Проверить условия»; Low/Rejected → «Пропустить».
- Воспроизводимость: `score_run` хранит версии профиля, весов, словарей, модели и промпта и значения компонентов; одинаковые входы → одинаковый результат; LLM-часть кэшируется.
- Объяснение: топ-3 плюса, топ-3 минуса, риски; каждый пункт ссылается на Evidence.
- Обратная связь «полезно/нерелевантно» + причина; система предлагает корректировку весов, **не применяя её молча**.
- Dashboard: настройки «топ-N в день» и «минимальный балл».

## 10. Режимы работы

- **Radar** — автообновление источников класса A/B, обработка, уведомления; без откликов.
- **Quick Evaluate** — вставка URL/текста (в том числе LinkedIn, Telegram, письма) → полный разбор и карточка; ничего не отправляет и не создаёт документов.
- **Capture** — приём вакансий от расширения (раздел 5–6).
- **Copilot** — черновики письма/ответов и выбор версии резюме: каждое утверждение привязано к записи профиля/Skill ledger (источник показывается); числа и достижения вне профиля не подставляются — при нехватке данных задаётся вопрос; правки резюме — как diff с подтверждением; результат — черновик, ничего не отправляется и не нажимается на сайтах.
- **Auto Apply** (Этап 8, по умолчанию выключен): только для источников с `auto_apply_allowed = true`; никогда для LinkedIn; суточный лимит по умолчанию 0; режим dry-run; журнал; глобальная кнопка остановки; не отправлять при неизвестных обязательных ответах; не повторять отклик; не обходить CAPTCHA; при необходимости ручного шага — передать управление пользователю.

## 13. Безопасность и приватность

| Угроза | Требование |
|---|---|
| Запросы с чужих сайтов к localhost | Раздел 5.7: Bearer-токен, проверка Host/Origin, без CORS-заголовков, слушать только `127.0.0.1` |
| Вредоносный HTML/XSS в описании | Санитизация `ammonia` при приёме; UI не использует небезопасную вставку HTML; строгий CSP; внешние ресурсы в окне приложения запрещены |
| Prompt injection | Текст вакансии — только данные в отдельном поле; LLM без инструментов и сети; JSON-схема + проверка цитат; найденные инструкции игнорируются и дают сигнал legitimacy |
| Лишние права Tauri | Минимальные capabilities; без свободного доступа к shell/fs; валидация входов всех IPC-команд |
| Утечка ПДн в LLM | В модель идёт обезличенный профиль (без ФИО, телефона, e-mail, адреса); перед первым вызовом показывается точный состав данных; журнал отправок; режим «только локальная модель» |
| Секреты | Только системное хранилище; редактирование секретов в логах; экспорт без токенов; автотест поиска секретов в логах |
| Права расширения | Минимум (раздел 5.3); сайты площадок — через optional-права по явному решению пользователя; без `tabs`; без удалённого кода |
| Данные рекрутеров | Белый список полей; вырезание контактов в расширении **и** повторно в приложении |
| Цепочка поставок | Lockfiles, проверка зависимостей в CI, подписанные релизы и обновления (Tauri updater) |
| Хранилище | Шифрование БД (SQLCipher или аналог) — решение в 19; резервные копии шифруются |
По умолчанию телеметрии нет. Удаление всех локальных данных и экспорт данных пользователя — обязательные функции. При появлении синхронизации/облака требования к персональным данным (в т. ч. 152-ФЗ) пересматриваются отдельно.

## 15. Тестирование и критерии приёмки

### 15.1. Golden dataset
Не менее 200 вакансий RU+EN с ручной разметкой (направление, уровень, формат, график, зарплата, eligibility, дубли, исключения); создаётся на Этапе 0, пополняется.

### 15.2. Метрики (начальные цели; пересмотр после Этапа 0)
| Метрика | Цель |
|---|---|
| Разбор опубликованной зарплаты (сумма, валюта, период, gross/net) | Точность ≥ 95% |
| Классификация направления | Macro-F1 ≥ 0,85 |
| Eligibility | **0** ошибочных `russia_eligible` среди вакансий с явным исключением России (критично). Доля `eligibility_unknown` — отчётная метрика, не цель |
| Дедупликация | Precision ≥ 99%, recall ≥ 90% |
| Evidence | 100% цитат присутствуют в исходном тексте (автотест) |
| Rejected | 100% имеют Confirmed-основание и цитату (автотест) |
| Воспроизводимость | Повторный расчёт даёт идентичный Score |
| Idempotency | Повторная отправка пачки не создаёт дублей; `partial` не затирает `full` |
| Изоляция сбоев | Сбой любого коннектора не влияет на остальные (тесты на записанных ответах: 403, 429, CAPTCHA, смена структуры) |
| Производительность | Раздел 14 |

### 15.3. Тесты
- Модульные: нормализация, зарплата, словари, eligibility, фильтры, scoring.
- Контрактные: парсеры расширения и коннекторы на сохранённых ответах (`tests/fixtures`), включая сломанную верстку (проверка «не выдумывать значения»).
- Интеграционные: расширение → ingest API → pipeline → UI (в т. ч. приложение закрыто → очередь → доставка).
- Безопасность: запрос с чужого Origin/Host отклоняется; запрос без токена → 401; вакансии с prompt injection и скриптами не исполняются и не раскрывают данные; поиск секретов в логах; проверка CSP и capabilities.
- Кроссплатформенность: установка, обновление, удаление, миграция данных на macOS и Windows.
- Расширение: Chrome и Firefox; MV3-жизненный цикл воркера (усыпление/пробуждение); квоты `storage`.

### 15.4. Критерий готовности MVP
Пользователь задаёт профиль и критерии; получает вакансии минимум из трёх реально работающих источников (допускается один источник класса D/C-assist, если подтверждена недоступность альтернатив); видит выдачу без дублей с объяснимым Score и цитатами; отличает подтверждённую доступность из РФ от неизвестной; сохраняет вакансии и ведёт историю откликов; метрики 15.2 выполнены на golden dataset.
